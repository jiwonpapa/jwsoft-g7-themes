# 업종별 테마 제작 프로세스

상태: 실행 절차 초안. 이 문서가 모든 차수의 자동 실행 지시는 아닙니다.

| 단계 | 산출물 | 다음 단계로 가져갈 기준 |
|---|---|---|
| 1. 상품 기획 | 업종·고객·방문 목적·사이트맵·기능 분류 | 테마가 제공할 범위 |
| 2. 벤치마킹 | 동종 유료 상품 3~5개 비교표 | 채택할 원리·차별점·제외 기능 |
| 2a. 레이아웃 데이터 사전 제작·점검·삽입 실증 | 업종 메뉴·상품·옵션 설계, AI로 제작한 대표 본문·이미지, 실제 삽입 | 내용·이미지·관계 일치와 G7 실제 저장·메뉴·옵션 계약 확인 |
| 3. 도안 제시 | 같은 문구와 콘텐츠로 방향 2~3개 | 형님이 선택한 디자인 |
| 4. 디자인 규격 | 토큰·섹션·상태·반응형·에셋 규칙 | 실제 구현의 공통 기준 |
| 5. 대표 구현 | 분야별 실제 데이터를 넣은 G7 홈 1개 + 핵심 상세 화면 1개 | 편집 가능한 구현·반응형·실제 데이터 흐름 |
| 6. 확장 | 확정 사이트맵의 나머지 페이지 | 공통 규칙과 상품 범위 일치 |
| 7. 패키징 | 설치 ZIP·개발 키트·문서·데모 | 해당 테마의 전달물 완성 |

## 벤치마킹 방식

각 후보에 URL·확인일·페이지 구성·핵심 방문 흐름·편집 방식·반응형 특징·에셋 조건을 적습니다.
판매 설명, 데모 관찰, 구매 소스 확인을 구별합니다. 문서만 본 기능을 직접 시험했다고 쓰지 않습니다.
사진·레이아웃·문구를 복제하기보다 업종 정보와 행동 유도 방식에서 설계 원리를 추출합니다.

## 도안 방식

- 색만 바꾼 변형 대신 사진 중심·목록 중심·편집 잡지형처럼 구조가 다른 방향을 제시합니다.
- 각 방향은 홈 전체와 모바일 핵심 화면으로 비교합니다. 모든 페이지를 세 벌씩 만들지 않습니다.
- 실제 한글 문구와 현실적인 콘텐츠 길이를 사용합니다. 이미지 생성 도안은 개념이며 실제 기능 화면의 증거가 아닙니다.
- 도안 선택 뒤 글꼴·간격·크롭·상태를 수치와 토큰으로 확정합니다. 이미지 픽셀을 편집 계약의 원본으로 삼지 않습니다.

## 대표 구현과 확장

AI로 사전 제작하고 내용·이미지·관계를 점검한 게시물·상품·옵션·메뉴를 레이아웃 데이터 팩으로 만들어 실제 삽입합니다. 설치 시 랜덤 문장·사진으로 채우지 않습니다.
대표 콘텐츠는 도안 전에 마련하고, 전체 레이아웃 데이터 팩은 대표 구현 전에 준비합니다. [분류·제작 정책](field-taxonomy-and-layout-data-policy.md)과 [설치·보존·배포 기준](research/field-layout-data-feasibility-2026-09-08.md)을 따릅니다.
먼저 토큰·기본 컨트롤·대표 섹션·실제 G7 연결을 함께 완성합니다.
이때 확인한 컴포넌트와 토큰을 나머지 페이지가 재사용합니다. 한 페이지의 일회성 구성을 성급하게 범용 엔진으로 만들지 않습니다.
주요 방향이 바뀌는 경우에만 선택 내용을 다시 확인하며 버튼·간격 수정마다 사람 승인 절차를 새로 만들지 않습니다.

작업 종료 시 변경 파일, 관련 확인 결과, 커밋·푸시 여부, 남은 항목을 짧게 남깁니다.
