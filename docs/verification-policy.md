# 변경 범위에 따른 검증 정책

상태: 범위 선택 정책과 테마 하네스 1차 구현. 로컬 G7에서 공개 화면·모바일 동작·편집 저장·재진입을 수동 확인했으며 CI와 반복 가능한 G7 브라우저 자동화는 아직 없습니다.

## 목적

필요한 결함을 해당 범위에서 확인하고 마감합니다. 검사 양·반복 횟수를 품질의 대리 지표로 쓰지 않습니다.
제품 소스의 정적 규칙과 실제 설치·편집 동작의 증거를 구별합니다.

| 변경 | 기본 확인 범위 |
|---|---|
| 문서·README 이미지·도안 | 참조 파일 존재·파일 형식·관련 링크·차이 확인 |
| 페이지 문구·레이아웃 | 해당 페이지 구조·변경된 화면 |
| 테마 토큰·스타일 | 해당 테마 스타일 가이드와 영향을 받는 대표 화면 |
| 공통 UI | 관련 단위 시험과 실제 사용하는 테마의 대표 동작 |
| G7 adapter·manifest/spec | 관련 공개 계약·편집 시나리오·필요 자산·검색엔진 시멘틱 매핑 |
| 게시판·문의 흐름 | 일반 브라우저의 작성·권한·열람·수정과 크롤러 HTML을 분리 확인 |
| 패키징·업데이트 | 대상 테마의 설치·누락 파일·고객 편집본 보존 |
| 출시 | 출시할 테마의 기획서에 정한 필수 상품 흐름 |

## 선택과 재사용 규칙

1. 실행 전에 대상 테마·파일·명령·선택 이유를 표시합니다.
2. 의존 관계를 따라 관련 검사만 선택합니다. 루트 설정 변경이라는 이유만으로 모든 테마를 선택하지 않습니다.
3. 성공 재사용은 명령·실제 의존 입력·도구 환경에 묶습니다. SHA 변화만으로 전부 무효화하지 않습니다.
4. 실패 검사를 자동으로 반복하지 않습니다. 원인을 수정한 뒤 실패 검사와 영향을 받은 후속 검사만 실행합니다.
5. 미분류 입력은 범위 결정 오류로 보고합니다. 전체검사로 자동 승격하지 않습니다.
6. 문서 자산(PNG/WebP/SVG 등)을 별도 분류합니다. 문서 이미지 때문에 제출이나 배포가 제품 검사로 넘어가지 않아야 합니다.
7. 입력을 추적할 수 없으면 성공 재사용만 제한하고 검사 범위를 확대하지 않습니다.
8. 제출·통합·CI에 같은 계획을 사용할 경우 동일 입력의 결과를 재사용하도록 구현합니다.

## 강제·권장·참고 구분

- 강제 후보: 깨진 manifest/참조, 노출된 비밀 값, 금지 의존성, 실제 실패 동작, 패키지 누락.
- 권장: 적절한 이미지 압축·CSS 중복 감소·시각 밀도 개선. 실제 문제가 없으면 전부 출시 차단으로 만들지 않습니다.
- 참고: LOC·번들 크기·점수 추이. 수치만으로 무조건 실패시키지 않습니다.

성능 예산은 대표 구현에서 G7 공통 비용과 테마 추가 비용을 분리해 측정한 뒤 정합니다.
정적 문서·레이아웃 변경에 불필요한 신규 단위 시험이나 상시 전체 coverage를 만들지 않습니다.
브라우저 시험은 실제 편집·저장·공개 흐름에 사용하며 단순 검사 등록 성공을 제품 동작 성공으로 보고하지 않습니다.
크롤러 응답은 일반 브라우저 응답으로 대신하지 않습니다. 권한상 볼 수 있는 범위에서 시멘틱 태그와 내부 링크가 유지되는지 별도 확인합니다.

## 종료 조건

선정한 필수 확인이 통과하면 마감합니다. 남은 미관 개선과 비차단 정리는 별도 항목으로 남깁니다.
도안 선택 외에 상시 사람 검수·최종 승인 단계를 임의로 추가하지 않습니다.
하네스 자체가 범위를 넓히면 실행을 중단하고 원래 범위로 선택 규칙을 수정합니다.

현재 실행 명령과 강제 항목은 [테마 하네스](theme-harness.md)에서 확인합니다. 하네스 통과는 정적 계약·의존성·빌드·설치 ZIP의 증거이며 실제 G7 설치·편집 동작의 증거를 대신하지 않습니다.
