# 테마 제작 헌법 v0.1

상태: 초기 작업 원칙. 자동 검사 구현 여부는 별도이며, 상품별 사양과 구체적인 수치는 아직 확정 전입니다.

## 1. 상품의 정의

판매 단위는 구매자가 자기 콘텐츠로 수정해 운영할 수 있는 업종별 G7 테마입니다.
홈만 꾸미거나 같은 레이아웃의 색상만 바꾼 것을 서로 다른 업종 상품으로 세지 않습니다.
목록·상세·문의·오류·모바일·편집·업데이트 경험을 상품 범위에 맞게 함께 설계합니다.

## 2. 저장소와 기능 소유권

- 테마 제작은 G7 코어와 Page Builder의 별도 제품입니다.
- G7이 인증·권한·원본·저장·Undo·렌더링을 소유하며 테마는 공개 계약을 사용합니다.
- 예약·결제·재고·CRM 등 업무 로직을 장식용 테마에 숨겨 넣지 않습니다. 필요한 기능 모듈을 명시합니다.
- 업종 기능의 부재를 작동하지 않는 버튼·가짜 성공 응답으로 가리지 않습니다.
- 지원 호스트 API가 없으면 필요한 계약과 대안을 명시합니다. private hook·전역 DOM 조작으로 우회하지 않습니다.

## 3. 재사용과 차별성

- 공통화 대상은 접근성 동작, 기본 컨트롤, 토큰 규격, G7 연결, 검사·패키징입니다.
- 테마별 사진·타이포·밀도·색상·정보 구성은 독립적으로 설계합니다.
- 공통 코드·규칙은 중앙 원본 하나에서 관리하고 릴리스 시 필요한 버전을 동봉합니다.
- 첫 테마의 실제 필요를 넘어 추상 엔진을 선행 제작하지 않습니다. 두 번째 테마에서 중복과 차이를 확인합니다.

## 4. 디자인과 편집 계약

- 도안 선택 후 토큰과 섹션 규칙을 정하고 실제 브라우저 대표 구현을 기준으로 확장합니다.
- 스타일 값은 의미 토큰을 재사용하며 예외는 해당 테마의 이유와 범위로 한정합니다.
- 원본 사진과 한글 문구를 교체해도 레이아웃이 유지되어야 합니다. 고정 높이와 수동 줄바꿈에 의존하지 않습니다.
- 변경 가능한 필드·슬롯·반복 항목·변형을 선언합니다. 지원된 선택지는 같은 G7 명령과 저장 경로를 사용합니다.
- 스타일 토큰 일치는 시각 품질 증명이 아닙니다. 정보 위계·사진·문구·브라우저 출력도 대표 구현에서 확인합니다.

## 5. 구현 품질

- TypeScript strict와 작은 책임별 모듈을 기본으로 합니다. 신규 any·이중 타입 단언으로 입력 검사를 대체하지 않습니다.
- CSS·편집 선택지·컴포넌트의 토큰 정의를 수동으로 중복하지 않습니다.
- React와 호스트 공유 런타임은 지원 G7 계약에 맞춥니다. 고객 서버는 사전 빌드된 자산을 사용합니다.
- G7과 테마의 표현식·번역·반복·actions·responsive·출처·알 수 없는 필드는 허용된 변경 밖에서 보존합니다.
- 구매자 콘텐츠와 테마 기본값의 업데이트 충돌을 자동 덮어쓰기로 해결하지 않습니다.

## 6. 에셋과 판매 경계

- 코드·폰트·이미지·아이콘은 출처와 동봉 권리를 구분합니다. 사이트 사용 가능과 템플릿 재배포 가능은 별도 확인합니다.
- 외부 유료 테마는 벤치마크입니다. 원본·수정본·데모 사진을 권리 확인 없이 재판매하지 않습니다.
- 데모 전용 에셋과 구매자에게 포함되는 에셋을 판매 설명에 구분합니다.
- 고객 정보·계정·API 키·개발자 인증 설정·다른 테마 소스는 판매 패키지에서 제외합니다.
- 가격·지원 기간·사용 사이트 수·갱신 정책은 별도 상품 결정이며 이 문서로 임의 확정하지 않습니다.

## 7. 검증 비용과 종료

검사는 변경 목적과 실제 영향에 비례합니다. 성공한 검사 반복, 문서 수정 후 전체 빌드, 테마 하나 수정 후 전체 테마 재검사는 기본 동작으로 만들지 않습니다.
검사 하네스는 범위·실행 이유·실패 대상을 설명해야 합니다. 실패를 자동 반복하거나 전체 검사로 승격하지 않습니다.
결과가 완성되면 해당 범위를 마감합니다. 선택적 정리·추가 개선을 완료 조건으로 계속 붙이지 않습니다.
